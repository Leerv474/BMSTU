# Методология Getting things done (Доведение дел до завершения)

Возникновение необходимости использования методологий личной продуктивности исходит из растущих темпов жизни и информационных потоков. Всвязи с этим на человека падает все большая когнитивная нагрузка, связанная с управлением собственными ежедневными задачами. При отстутсвие какой-либо структуры в данном случае становится все сложнее и сложнее поддерживать высокий уровень продуктивности.

Методология Getting things done (Далее GTD) - с переводе с английского Доведение дел до завершения - это метод повышения личной продуктивности, посредством организации и контроля задач, созданный Дэвидом Алленом.

Ее суть заключается в планомерном подходе к решению дел посредством следующих 5-ти шагов:

- сбор информации о текущих задачах
- обработка
- организация
- обзор 
- действия

в процессе обработки и оргнаизации, задачи расдеяются на категории:

- корзина: исходный необработанный список задач
- проекты: список задач, выполнение которых требует множества шагов

и списки, отражающие статус задачи
- текущие: задачи выполняемые на настоящий момент
- отложенные: задачи, не трубующие незамедлительного выполнения
- ожидание: задачи, зависящие от внешних факторов
- и выполненные.

# Предметная область

Итак, Предметная область заключалась в разработке приложения управления персональными задачами, в которую интегрирован процесс обработки задач по описанной ранее методологии.

В качестве механизма хранения и отображения задач был использован подход Kanban, который предусматривает создание списков (таблицы) задач соглано их статусами и группироку этих списков в общие хранилища - доски.

Таким образом Методология GTD была интегрирована с подходом Kanban следующим образом:
в рамках одной доски предусмотрены статус-таблицы по-умолчанию: Корзина, Ожидание, Текущие, Отложенные, Выполнено. Создание задачи автоматически помещает задачу в корзину и предлагает распределение задачи. Задачи между статусами переходят по команте прохождения текущего статуса. Из Отложенных в текущие, из текущих или ожидание в выполнено. Также предусмотрено создание пользовательских статусов, если перед конечным выполнением задачи пользователь желает указать промежуточные состояния задач.

Проекты были реализованы как список, прикрепленный к каждой доске и ссылающийся к задачам на самой доске. Таким образом существующие задачи могут собраться в проекты для их объединения. Из статусы отследживаются и управляются индивидуально. Таким образом предоставляется общая точка доступа к группам задач, следующих одной цели.

# Существующие программные решения

В качестве основных аналогов были рассмотрены системы Microsoft Todo, Weeek, Trello и Todoist.
Microsoft Todo является самым простым из них для хранения заметок пользователей, базовый фукнционал жизненного цикла задач и их группировки. Системы Weeek, Trello и Todoist предлагают гибкие подходы оргназации задач и обширный функционал заточненный на коммерческое использование, работу с группами лиц. 

Результаты анализа позволили вывести наиболее эффективные способы реализации функционала системы хранения задач. Однако сущестующие решения не предусмотрены для индивидумального использования и соответсвенно не распологают методами повышения личной эффективности.

Таким образом, используя результаты анализа был выбран подход хранения задач Kandan, на основе которого бала интегрирована методология GTD.

# Архитектура

Приложение реализовано на основе клиент-серверной архитектуры. Серверная часть представляет собой REST API, осуществляющее обработку HTTP/HTTPS-запросов и обмен данными в формате JSON.

Клиентские части приложения — мобильный и веб-клиент — отправляют запросы к серверной части для обработки бизнес-логики.

# Серверная часть
Доступ клиента управляется посредством использования JWT аутентификации, реализованной на основе библиотеки Spring Security.

Взаимодействие серверной части с базой данных было реализовано с помощью библиотеки Spring Hibernate, которая реализует объектно-реляционное отображение.
Было реализовано управление жизненным циклом каждой сущности, внедрен алгоритм организации задач по GTD.
А также было проведено ручное тестирование API.

# Клиентская часть
Графический интерфейс представел в виде модифицированных Kandan досок. В реализованной системе, к каждой доске прикрепляется список проектов. Каждая доска создается с рядом таблиц, заданных методологией GTD:

- корзина
- отложенное
- текущие
- ожидание
- выполнено

Было предусмотрено добавление пользовательских статусов при создании или редактировании доски.

Методология исполняется сразу с этапа создания задачи: пользователю предлагается положить задачу в корзину или сразу начать ее распределение.

В окне распределения задачи пользователю предлается устанавливать таблицу хранения задачи согласно подсказкам интерфейса.
